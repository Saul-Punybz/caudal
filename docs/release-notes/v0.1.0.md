# Caudal v0.1.0

First tagged release. Caudal is an open-source rewrite of
[MistServer](https://github.com/DDVTECH/mistserver) in Rust: one publisher
in, many viewers out, over the protocols people actually use in 2026. This
is an early release — read "NOT verified" and "Known limits" below before
running it anywhere that matters.

## What works

- **Ingest:** RTMP/E-RTMP, SRT, WHIP (WebRTC), RTSP pull, MoQ (a `hang`
  broadcast over WebTransport), and a 24/7 channel built from a playlist of
  files.
- **Scale:** origin/edge clustering (an edge pulls a stream from its
  origins over MoQ on the first viewer) and backup-source failover.
- **Output:** LL-HLS (multi-rendition, rendition reports), WHEP, MoQ/
  WebTransport, SRT push/listen, an RTSP server (TCP interleaved, UDP
  unicast, RTSPS), IP multicast output (MPEG-TS and RTP), SCTE-35 cues
  (`EXT-X-DATERANGE` and legacy `EXT-X-CUE-*`, plus TS splice), and
  multistreaming RTMP/RTMPS restream to other platforms.
- **Processing:** transcoding ladders (ffmpeg by default, or an in-process
  pure-Rust H.264 encoder/decoder), recording with schedules, VOD, and
  clips.
- **Platform:** TOML config with hot reload, a REST API, Prometheus
  metrics, TLS/HTTP2/ACME, per-protocol auth tokens plus webhooks, an admin
  login for the UI/API (local argon2id passwords, OIDC/SSO, or API
  tokens), geo-blocking and IP allow-lists, stream health alerts, live
  captions (local Whisper-class speech-to-text via `candle`, Spanish and
  English verified) published as WebVTT in LL-HLS, a web UI (Overview,
  Stream, Publish, Channels, Restreams, Recordings, Login), `caudal doctor`
  for setup diagnostics, and `caudal import-mist` to migrate a MistServer
  config.
- **Distribution:** static musl binaries for x86_64 and aarch64, a
  `FROM scratch` container image, and a Helm chart.

## Verified

- The full workspace test suite (`cargo nextest`) is green on every merge,
  including integration tests that drive real RTMP/HLS/SRT/WHIP/WHEP/
  RTSP/MoQ traffic end to end (see `.github/workflows/ci.yml`).
- LL-HLS output is checked against Apple's `mediastreamvalidator` on the
  macOS CI runner when it's available there.
- IP multicast output was checked against `ffprobe`, `ffmpeg`, and TSDuck.
- The OMT `vmx-codec` port (separate repo,
  [`open-media-transport`](https://github.com/Saul-Punybz/open-media-transport))
  was checked byte-identical to `libvmx` in both directions.
- A side-by-side benchmark against MediaMTX v1.21 on one machine, redone on
  GitHub's Linux runners after fixes
  (`docs/research/BENCH-MEDIAMTX.md`, measured 18-19 Sep 2026):
  - Binary size and idle RSS: Caudal is about 2.5x smaller/lighter.
  - LL-HLS fan-out at 100-1,000 viewers: Caudal uses roughly half the CPU
    and less memory than MediaMTX.
  - RTSP fan-out, after the 19 Sep send-path fix (measured on GitHub Linux
    runners): Caudal uses about a fifth to a sixth of MediaMTX's CPU
    (x100 11.5 % vs 63 %, x300 30 % vs 184 %). Before that fix,
    on the Apple M4 laptop, MediaMTX was about 15% lighter — see the doc
    for both numbers.
  - WHEP (WebRTC) at 300 viewers, on GitHub's Linux runners with batched
    sends (GSO): all 300 viewers kept up in all 5 repetitions, 1,803 Mbps
    delivered, 179 % CPU — in the same session MediaMTX kept 0 of 300 and
    delivered 873 Mbps at 157 % CPU, and Caudal without batching kept 30
    of 300. At 100 viewers: 60 % CPU vs MediaMTX's 104 %.
  - LL-HLS and RTSP latency (median/p95): a tie with MediaMTX.
  - RSS with one live stream (1080p30, 6 Mbps, no viewers) on the Linux
    runners: 55 MB ten seconds in and 65 MB at steady state, against
    MediaMTX's 84 and 93 MB in the same runs. Before this release's
    memory work Caudal used 90 and 145 MB; a heap profile found the RTMP
    ingest holding whole buffers alive through slices, a second 30 s copy
    of every stream in the MoQ track cache, and LL-HLS keeping each
    completed segment twice. The default `[buffer] window_secs` also
    dropped from 50 to 15 (see "Known limits").
  - "Faster" is only claimed for the specific metrics measured above, on
    the machines listed in the doc — not as a general statement.
- `fuzz-smoke` builds and runs every fuzz target for 60s against its saved
  corpus on every push, to catch build breaks and regressions (this is a
  smoke test, not real fuzzing depth — see `fuzz/README.md`).
- The release pipeline itself (this file's own tag) was exercised with a
  `workflow_dispatch` dry run: both static binaries built, `--version`
  printed the right version, `caudal check` accepted
  `caudal.example.toml`, both container platforms built from those
  binaries, and the amd64 image answered `/healthz` under `docker run`
  with a minimal `[admin]` config, all on a GitHub Actions runner. Nothing
  in that dry run was published (no GHCR push, no GitHub Release, no
  `latest` tag).

## NOT verified

- **No production or long-running deployment.** The soak test ran on
  GitHub's runners, not against a real workload or real network
  conditions: 30 minutes with 3 publishers and 63 viewers across LL-HLS,
  RTSP and WHEP, with publisher restarts, a config reload and a clip —
  RSS trend -15 MB/h (memory fell), file descriptors and threads flat, no
  errors or timeouts. Hours, not days; one machine; synthetic traffic.
- **Origin/edge clustering is built but only tested on one machine**
  (in-process multi-node tests and an end-to-end test with separate
  binaries on loopback; see `docs/research/CLUSTER.md`). It has not run
  across separate hosts or real networks, and the Helm chart deploys a
  single node. Per-stream failover to a backup source is separate from
  clustering.
- **Not built at all:** MoQ playback on Safari, DASH output, kTLS +
  `sendfile`, an `io_uring`/pacing evaluation, GPU transcoding,
  watermarking, CEA-608 captions in TS, player SDKs, a Raspberry Pi image,
  and the MCP server (`caudal mcp`) — see PLAN.md's backlog for the full
  list and status of each.
- **The MistServer comparison never finished.** A `bench/mistserver`
  branch that builds MistServer 3.11.2 for the same benchmark was set
  aside mid-project (build/runtime library issues); every "vs" number in
  this release is against MediaMTX, not MistServer.
- **WHEP at 1,000 viewers** was not re-measured after the 19 Sep WebRTC
  send-path fixes — the load-generating laptop, not the server, was the
  bottleneck at that scale in the last run that reached it.
- **No security audit beyond `cargo deny`** (license and advisory
  database checks) and the fuzz smoke tests above. No third-party pen
  test, no CVE history yet (first release).
- Benchmarks were measured on one Apple M4 laptop plus GitHub's shared
  Linux runners — not a range of hardware, and the laptop runs were not on
  an idle machine (see the "Not idle" note in `BENCH-MEDIAMTX.md`).

## Known limits

- The Helm chart deploys a single node. Running more than one replica
  behind one load balancer gives you N independent servers; an
  origin/edge cluster needs the `[cluster]` section on each node (see
  `caudal.example.toml`), which the chart does not set up.
- **`[buffer] window_secs` now defaults to 15 seconds** (was 50). Players
  start at the live edge and LL-HLS keeps its own segment window, so the
  extra 35 s only helped a consumer more than 15 s behind live, and it
  cost about 26 MB per 6 Mbps stream. Raise it if you rely on DVR-style
  rewind deep into the buffer or want more pre-roll when a recording
  starts mid-stream.
- The container image is `FROM scratch` (no shell, no package manager) and
  **intentionally refuses to bind to a non-loopback address without an
  `[admin]` login configured** — this is a deliberate safety default, not
  a bug. To run the image reachable from outside the container, mount a
  `caudal.toml` with an `[admin]` section (local users, OIDC, or API
  tokens) or explicitly set `[admin] allow_unauthenticated = true` to
  accept the risk. See `caudal.example.toml`'s `[admin]` block and the
  Helm chart's README ("Admin login") for worked examples.

## Getting it

- **Static binaries:** `caudal-0.1.0-x86_64-unknown-linux-musl.tar.gz` and
  `caudal-0.1.0-aarch64-unknown-linux-musl.tar.gz`, each containing the
  `caudal` binary, `LICENSE-MIT`, `LICENSE-APACHE`, `README.md`, and
  `caudal.example.toml`. Verify against `SHA256SUMS` in this release.
- **Container image:** `ghcr.io/saul-punybz/caudal:0.1.0` (also tagged
  `:latest`), multi-arch (`linux/amd64`, `linux/arm64`), built from the
  same static binaries above — no separate build happens inside Docker.
- **Helm chart:** `deploy/helm/caudal` in this tag, `appVersion`/`version`
  0.1.0.
